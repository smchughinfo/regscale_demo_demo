# Session Memory: Business Model Graph Implementation
**Date:** September 30, 2025 - 5:31 AM
**Topic:** Building interactive D3.js business model graph for RegScale Hydrator

## Session Overview
This session focused on enhancing the RegScale Hydrator UI with a visual representation of the entity relationships in our data model. We built an interactive force-directed graph using D3.js that shows how all 11 RegScale entity types relate to each other.

## What We Built

### 1. Entity Reference Cards (UI Polish)
- **Task:** Display the 11 RegScale entity types (from used_entities.md) on the Hydrator page
- **Initial Approach:** Tried Bootstrap accordion - user didn't like it
- **Final Design:** Colorful card grid with distinct colors for each entity type
  - Organizations (Blue), Facilities (Green), Accounts (Cyan), Security Plans (Yellow)
  - Catalogues (Red), Security Controls (Gray), Components (Black), Assets (Purple)
  - Risks (Orange), Assessments (Teal), Supply Chain (Pink)
- **Layout:** 3-column responsive grid (collapses to 1 column on mobile)
- **Content:** What, Our Use, Key Fields, Links To/Contains info

### 2. Collapsible Sections with Persistent State
- **Feature:** Made three sections collapsible with state saved to hydration.json
  - Used RegScale Entities Reference
  - Utility Methods (GET)
  - Creation Methods (POST/PUT/PATCH/DELETE)
- **Implementation:** Added `uiState` object to hydration.json with boolean flags
- **UX:** Click header to toggle, chevron icon shows state, auto-saves on change
- **User Feedback:** "really REALLY good job. excellent"

### 3. Business Model Graph (Main Feature)
**Goal:** Visualize relationships between entity types, not individual entities

#### Technical Stack
- **Library:** D3.js v7 (force-directed graph)
- **Why D3:** Industry standard, highly customizable, perfect for network graphs
- **Integration:** React component with refs and useEffect

#### Graph Structure
**11 Nodes (Entity Types):**
- Organizations, Facilities, Accounts, Security Plans, Catalogues
- Security Controls, Components, Assets, Risks, Assessments, Supply Chain

**Two Types of Edges:**
1. **Structural/Contains (solid lines):**
   - Organizations → {Facilities, Accounts, Security Plans, Catalogues}
   - Security Plans → {Components, Assets, Risks, Assessments, Supply Chain}
   - Catalogues → Security Controls

2. **References (dashed lines):**
   - Security Controls → {Security Plans, Components, Accounts}
   - Components → Accounts
   - Assets → {Facilities, Accounts}
   - Risks → {Components, Security Controls, Accounts}
   - Assessments → {Components, Facilities, Accounts}
   - Supply Chain → Accounts

#### Visual Design
- **Node Size:** 30px radius circles (35px on hover)
- **Node Colors:** Match the entity reference cards for consistency
- **Entity Count Badges:** White number in center of each node
- **Directional Arrows:** SVG markers show relationship direction
- **Legend:** Shows solid vs dashed line meanings

#### Interactive Features

**1. Hover Tooltips:**
- Shows entity type name and count
- Lists first 5 instances with name + key detail
  - Example: "Sarah Chen - CEO", "Mike Rodriguez - VP Engineering"
- "...and X more" if there are more instances
- Clean white tooltip with drop shadow

**2. Click to Focus (The Killer Feature):**
- Click any node → highlights that node + all connected nodes
- Dims unconnected nodes to 20% opacity
- Highlights connecting edges, dims others
- Click again or click background to reset
- **Default:** Assessments node selected on load (shows immediate interactivity)

**3. Responsive Design:**
- SVG width: 100% of container
- Dynamic viewBox based on container width (min 800px)
- `preserveAspectRatio="xMidYMid meet"` maintains proportions
- Window resize listener redraws graph

**4. Force Simulation Tuning:**
This was the trickiest part. Initial graph had nodes clustered in tiny center area.

**Problem:** Nodes only using ~20% of canvas
**Solution:** Tuned force parameters aggressively
- Link distance: 150 → 250 (push nodes apart)
- Charge strength: -300 → -800 (strong repulsion)
- Collision radius: 50 → 80 (more personal space)

**User:** "check screen 5 soo how the bundle itself oly takes up a tiny portion of the canvas?"
**Fix:** Stronger forces spread nodes across full canvas
**User:** "yep, that looks better"

#### Data Extraction
Built `extractEntities()` function that:
- Parses hydration.json calls array
- Filters successful POST/PUT/PATCH calls (statusCode 200)
- Groups by entity type based on URL
- Extracts name + key detail for each instance
  - Organizations: name + status
  - Accounts: firstName lastName + title
  - Components: componentName + componentType
  - Risks: riskStatement (truncated) + status
  - Etc.

**Actual Data Counts:**
- Organizations: 3 (Health Widgets Inc, Engineering, QA, Manufacturing)
- Facilities: 3
- Accounts: 5
- Security Plans: 5
- Components: 18
- Assets: 14
- Risks: 21
- Security Controls: 20

- Supply Chain: 4

## Key Technical Decisions

### Size Iterations
The graph went through several size adjustments:

1. **Original:** 1000x700 - Good baseline
2. **User:** "can we double its size?"
3. **Attempt 1:** 2000x1400 - Nodes became tiny dots
4. **User:** "that made the nodes smaller"
5. **Attempt 2:** 1500x1050 - Still not quite right
6. **Final:** Back to 1000x700 + stronger forces = **Perfect**

**Lesson:** In force-directed graphs, spreading is about forces, not canvas size!

### Removed Features
- **Untangle Button:** Initially added a button to "reheat" simulation (reset alpha to 1)
- **Why Removed:** Click-to-focus feature made this obsolete - you can just click nodes to see relationships clearly
- **User:** "the highlight thing you just added solved that problem better"

### Instructions Text
Added clear user guidance at top of graph:
> "Click on a node to highlight its relationships. Click again or on the background to reset."

## Technical Challenges & Solutions

### Challenge 1: Graph too clustered
**Problem:** All 11 nodes bunched in center, using 20% of canvas
**Attempted Fix:** Double canvas size (made nodes tiny)
**Real Solution:** Increase force strengths, not canvas size

### Challenge 2: Bash script syntax errors
**Problem:** Node script with `!==` causing shell escape issues
**Solution:** Use separate .js file instead of inline eval

### Challenge 3: State persistence
**Problem:** Collapsible sections don't remember state on reload
**Solution:** Store `uiState` in hydration.json, auto-save on toggle

### Challenge 4: Responsive graph sizing
**Problem:** Fixed size graph doesn't adapt to container width
**Solution:**
- Use containerRef to measure actual width
- Set SVG width to 100%
- Dynamic viewBox with preserveAspectRatio
- Window resize listener

**The Fix:**
Stronger forces, not bigger canvas. This is a great reminder that force-directed graphs need force tuning, not size tuning.
